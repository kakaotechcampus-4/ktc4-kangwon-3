# 테스트 가이드

테스트 실행 방법과 작성 규칙입니다. 파트별 테스트 규모와 전략은 [테크스펙 – 테스트 전략](테크스펙.md#테스트-전략)에 있습니다.

## 공통 원칙

- 기능을 바꾸면 테스트를 함께 바꿉니다.
- 외부 서비스(LLM, 법제처, 소셜 API, AI 서버)는 테스트에서 가짜로 바꿉니다. 실제로 부르는 테스트는 따로 표시합니다.
- 버그를 고칠 때는 그 버그를 재현하는 테스트를 먼저 씁니다.

## BE

테스트 종류 선택 기준, 작성 규칙, 커버리지 기준은 [BE 테스트 정책](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/blob/develop/backend/docs/TEST_POLICY.md)에 있습니다.

```bash
cd backend/beforeselling
./gradlew test
./gradlew test --tests "*ProductServiceTest"
```

| 종류 | 쓰는 경우 | 도구 |
|---|---|---|
| 단위 | 엔티티 상태 전이, 서비스 로직 | JUnit 5, Mockito |
| 컨트롤러 슬라이스 | 요청 검증, 응답 형식, 인증 | `@WebMvcTest` |
| 저장소 슬라이스 | 쿼리, 연관관계 매핑 | `@DataJpaTest` (H2) |
| JSON 슬라이스 | 콜백 DTO 역직렬화 | `@JsonTest` |
| 통합 | 여러 단계 흐름(답변 → 재진단, 재시도, 동시 삭제) | `@SpringBootTest`, Awaitility |
| 수동 | 실제 SES·Redis 확인 | 환경변수가 있을 때만 실행 |

작성 규칙:

- `@DisplayName`은 "~테스트"가 아니라 동작과 결과를 문장으로 씁니다.
  - 예: `@DisplayName("만료된 리프레시 토큰으로 재발급하면 AUTH-003을 반환한다")`
- Given / When / Then 구조로 씁니다.
- 외부 HTTP는 `MockRestServiceServer`로 대신합니다.
- 테스트 DB는 H2(PostgreSQL 모드)입니다. Redis가 필요한 통합 테스트는 Testcontainers로 Redis 7을, Flyway 마이그레이션 검증은 PostgreSQL 16을 띄웁니다. Docker가 없으면 이 테스트들은 건너뜁니다.

## AI

```bash
cd ai
pytest                     # 기본 (외부 API 테스트 제외)
pytest tests/pipeline      # 폴더 단위
pytest -m external_api     # 실제 외부 API (키 필요)
```

작성 규칙:

- 외부 API는 `httpx.MockTransport`(`tests/clients/conftest.py`의 `wire` fixture)로 대신합니다.
- 법령·결정사례 응답은 실제 응답을 저장한 픽스처(`tests/fixtures/`)를 씁니다.
- 모델 호출은 가짜 에이전트로 바꿉니다.
- 실제 외부 API를 부르는 테스트는 `tests/integration/`에 두고 `external_api` 마커를 붙입니다.

### 품질 평가는 테스트와 따로 돌립니다

모델 응답의 품질은 단위 테스트가 아니라 평가셋으로 잽니다. 프롬프트나 추출 규칙을 바꾸면 평가를 돌려 전후를 비교하고, 결과를 PR 본문에 남깁니다.

```bash
python -m app.eval.runner --all --runs 5
```

방법: [AI README – 품질 점검](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/blob/develop/ai/README.md#품질-점검)
