# 모니터링과 장애 대응

## 모니터링 구성

| 도구 | 보는 것 | 위치 |
|---|---|---|
| Grafana | BE API 응답시간·에러율, JVM, DB 커넥션 풀, 컨테이너, 호스트 | https://palgijeone.com/grafana/ |
| Prometheus | BE(`/actuator/prometheus`), AI(`/metrics`), 호스트(node-exporter), 컨테이너(cAdvisor) 지표 수집. 7일 보관 | EC2 내부 |
| Sentry | FE·BE·AI 예외(BE는 5xx만), BE 트레이스(운영 10%)·프로파일. 새 이슈는 Lambda를 거쳐 Discord 파트별 채널로 알림 | Sentry 프로젝트, [알림 Lambda](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/tree/develop/infra/lambda/sentry-discord-notifier) |
| AI 지표 | `/metrics`(세션, 단계별 시간, 토큰·비용, 콜백, Tool) | AI 서버 내부 |
| AI 사용량 로그 | 모델 호출별 토큰과 예상 비용(`logs/usage.jsonl`) | AI 컨테이너 볼륨 |

- 대시보드: **beforeselling 서비스 개요**, **AI 서버 개요**, **beforeselling 부하 테스트**
- 설정: [`infra/monitoring`](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/tree/develop/infra/monitoring)

## 장애 대응 순서

1. **범위 확인**: https://palgijeone.com, `/v3/api-docs`, `/api/ai/v1/health/ready` 중 어디가 안 되는지 확인합니다.
2. **최근 배포 확인**: [Actions](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/actions)에서 직전 배포가 실패했거나 방금 배포됐는지 확인합니다.
3. **지표·에러 확인**: Grafana에서 응답시간·에러율·자원을 확인하고 Sentry에서 새 예외를 확인합니다.
4. **조치**: 아래 표를 따릅니다.
5. **공유**: 팀 채널에 증상, 원인, 조치를 남기고 필요하면 이슈를 생성합니다.

## 증상별 조치

| 증상 | 먼저 볼 것 | 조치 |
|---|---|---|
| BE 배포 후 API 오류 | `backend.yml`의 "서비스 확인" 단계 | EC2에서 `blue-green.sh rollback` ([BE 배포 문서](https://github.com/kakaotechcampus-4/ktc4-kangwon-3/blob/develop/backend/beforeselling/deploy/README.md#수동-롤백)) |
| FE 화면이 깨짐 | 직전 FE 배포 | `frontend-deploy.yml`을 이전 SHA로 수동 실행 |
| AI 배포 실패 | `ai.yml`의 헬스 확인 로그 | 원인 수정 PR 또는 되돌리는 PR 병합 |
| 진단이 진행 중에서 멈춤 | AI 로그의 `run_id`, BE 로그 | 15분이 지나면 BE가 자동으로 실패 처리. 사용자는 재시도 가능 |
| 진단이 대기(`PENDING`)에 머묾 | AI 서버 상태 | BE가 60초마다 다시 요청하고 10분이 지나면 실패 처리 |
| 429가 많이 남 | 사용자별 요청량 | 처리율 제한 정상 동작. 한도는 `RATE_LIMIT_*` 환경변수로 조정 |
| Redis 장애 | Redis 컨테이너 상태 | 처리율 제한은 건너뛰고 통과. 로그인·재발급은 실패하므로 Redis 복구 |
| nginx 설정 배포 실패 | `infra-nginx.yml`의 `nginx -t` | 실행 중인 nginx는 이전 설정 유지. 설정을 고쳐 다시 배포 |

## 로그 보는 법

| 대상 | 명령 (EC2) |
|---|---|
| BE | `docker logs be-server-blue` 또는 `be-server-green` (서비스 중인 색은 `/etc/nginx/be-upstream.conf`) |
| AI | `docker logs ai-server` |
| nginx | `/var/log/nginx/` |

- AI 로그는 줄마다 `diagnosis_id`, `product_id`, `run_id`가 있어서 진단 한 건을 따라갈 수 있습니다.
