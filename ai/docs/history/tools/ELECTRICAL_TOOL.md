## #823 문서 재작성 (2026-11-11)

- 본문을 현재 동작만 기술하는 형식으로 재작성하였다. 공용 설명은 [TOOL_COMMON.md](../../current/tools/TOOL_COMMON.md)로, 경위·측정·남은 작업은 이 파일로 이동하였다.
- 코드와 일치하지 않던 내용을 수정하였다.
  - 공용 모듈에 모델 호출 단계(`agent.py`)가 있다고 기술하였으나, 해당 파일은 없으며 모델 호출 단계는 `app/tools/base/steps.py`에 있다(11줄).
  - 전기저장장치 구성품 행 제외 조건을 "상품 원문" 기준으로 기술하였으나, 실제로는 원문과 대조된 조건의 값과 인용만 확인하며 확인 낱말에 에너지저장장치·전지시스템도 포함된다(48줄).
  - 법제처 응답을 API로 직접 조회한다고 기술하였으나, DB 캐시를 우선 조회한다(123줄).
  - DB에 조문 테이블(`law_articles`)이 있다고 기술하였으나, 해당 테이블은 존재하지 않는다(127줄).
  - 본문의 시행일을 검색 결과와 대조한다고 기술하였으나, 시행일은 대조하지 않고 로그만 기록한다(133줄).
  - 정보 부족 문구의 분기 조건에 `low_voltage`가 누락되어 있었다(141줄).
  - `query` 키 목록에 `search_terms`, `undecided`가 누락되어 있었다(144줄).
  - Tool 실행기 연결과 파이프라인 연결을 남은 작업으로 기술하였으나, 이미 연결되어 있다(158줄, 167줄).
- 문서에 없던 동작(조회어 구성, 전지 전용 시 전지·충전기 행 추가 조회, 전원 질문 회차 분리, 전기 조건이 없을 때의 질문 생략, 근거 첨부 조건, 품목명 정리)을 추가하였다.

## #796 보류 이유별 정보 부족 문구

(141줄)

>   - 요약은 보류 이유(`query["undecided"]`)에 따라 고른다 (#796). 저전압이라 후보 행이 모두 빠지면(`low_voltage`) "정격 전압(5V)이 저전압(교류 30V·직류 42V 이하)이라 … 대상에서 빠지는 범위입니다. 대상이 아닐 가능성이 높지만 확정은 아닙니다. 함께 오는 어댑터나 충전기는 따로 확인이 필요합니다", 전원·전압은 읽었는데 맞는 행이 없으면(`no_match`·`no_rows`) 읽은 값을 보여 주고 "… 확인했지만 해당하는 전기용품 품목을 찾지 못해", 전원·전압이 없거나 제품 종류가 없으면 기본 문구. 전지 전용이라 본체 행을 뺀 경우(`battery_only`가 true이고 `battery_only_excluded`가 있음)는 이보다 먼저 보고 "건전지나 충전지로만 동작하는 제품이라 본체는 … 빠질 수 있습니다. 내장 전지나 충전기가 대상인지는 판단하지 못했습니다"로 안내한다 (#804). 전원·전압을 읽었는데 "전기 정보를 찾지 못했다"고 안내하지 않게 하기 위함이다.

## 평가셋

- `tests/eval_truth_electrical/holdout.json`: 개발 샘플과 겹치지 않는 18개 상품과 예상 행(운용요령 별표 원문 기준, 사람 검토 전). 교류 220V 가전 위주다.
- `tests/eval_truth_electrical/usb_battery.json`: 실제 입력에 많은 USB·배터리 소형 제품 11개와, `tests/fixtures` 축약본을 추출 에이전트(gpt-4.1-mini)로 한 번 돌려 고정한 실제 추출 결과 8개(사람 검토 전).
  - 2026-10-12 결과(3회): luna(none) 정답 행 선택 9/12·조회 recall 12/12, mini 6/12·6/12. 정답 행이 없는 사례(본체 행을 고르면 안 됨)는 두 모델 모두 45/45.
  - 노트북 어댑터의 예상 행(직류전원장치)은 검토가 필요하다. 모델이 고른 "컴퓨터용 전원공급장치"(안전확인)도 맞을 수 있다.
- **이 셋을 보고 코드·프롬프트를 고치지 않는다.** 고치면 새 셋을 만든다.
- 프롬프트에는 상품 예시를 넣지 않는다(형식 규칙만 말로 설명).
- 실행: `python -m app.eval.electrical_runner --eval tests/eval_truth_electrical/holdout.json --runs 3`
  - 품목 행 선택 정확도를 잰다. 법적 판정이나 판매 안내(`required_actions`)의 정확도는 재지 않는다.
  - 실행 실패는 따로 세고 정답에서 뺀다. 조회 recall@k와 정답률은 정답 행이 있는 사례만으로, 정답 행이 없는 사례(본체 행을 고르지 않아야 함)는 별도 지표로 낸다.
  - 저장한 원자료는 `--eval … --rescore 원자료.json`으로 API 호출 없이 다시 채점할 수 있다.

## 재작성 전 계획·미구현 사항

(101-102줄, 109줄)

> "특례 없음"을 확정하려면 사람이 검토한 품목 ↔ 별표 13 대응 규칙이 필요하다(미구현).
> 판매 방식(구매대행/사입)은 상품 글에서 알 수 없으므로 두 경우의 할 일을 함께 낸다. 판매 방식을 진단 입력으로 받는 것은 BE·FE와 합의할 사항이다.
>
> | 확정 판단(`REQUIRED`/`NOT_REQUIRED`) | 사람이 검토한 코드 규칙만. **아직 없음** |

(150-158줄)


- 확정 규칙: 반복 실행에서 매번 같은 행이 나오는 품목부터, 사람이 법령 원문과 대조해 검토한 규칙으로 `REQUIRED`를 낸다.
- 조회 품질: 평가셋으로 정답 행이 상위 8개에 드는지(recall@8)를 측정한다. DB 벡터 조회로 바꿀 때 같은 지표로 비교한다.
- 비고의 제도 변경("이 경우 공급자적합성확인대상으로 한다", 6행)과 정격·용도 조건의 코드 판정.
- 공급자적합성확인대상의 구매대행 의무, 병행수입·수입 중고 특례, 안전성검사대상전기용품.
- 별표 13 대조는 품목명 일치다. 표현이 다르면 `unmatched`(확인 필요)로 나온다. 사람이 검토한 대응 규칙을 만들어야 "특례 없음"을 확정할 수 있다.
- 상품 본체와 동봉 부속품(어댑터·전지)의 조건을 구분하지 않는다. 저전압 판정은 상품 전체의 전원·전압 값을 한데 모아 모든 후보 행에 적용한다. 같은 뜻의 표기(USB/DC, 입력·출력 모두 5V)는 충돌로 보지 않지만, 본체 DC 12V와 어댑터 AC 220V처럼 교류·직류가 섞이면 여전히 충돌(판정 보류)이다. 부속품별 판단에는 조건에 대상(본체/어댑터/전지)이나 입력/출력 구분이 필요하다.
- ToolExecutor 연결은 agent-pipeline 머지 후 진행한다.

## 재작성 전 단독 실행 설명

(182-199줄)

파이프라인 없이 실제 모델·법제처 API로 Tool 하나를 돌려 볼 수 있다(비용 발생). `ai/`에서

```bash
python -m app.eval.electrical_runner                   # 내장 상품 6개
python -m app.eval.electrical_runner --only 전기포트 --runs 3
python -m app.eval.electrical_runner --model openai/gpt-4.1-mini --model openai/gpt-6-luna@LUNA \
    --default-temperature openai/gpt-6-luna --price openai/gpt-6-luna=152,15,761 --runs 3 \
    --out logs/eval/electrical-compare.json
python -m app.eval.electrical_runner --product product.json --json
```

- 품목표는 한 번 받아 캐시하고 최초 로드 시간을 따로 출력한다.
- 회차마다 모델 호출별 입력(캐시)·출력 토큰과 지연, 전체 시간, 조회 후보·선택 행·저전압 판정을 출력한다.
- 마지막에 모델별 평균·최대, 예상 비용, 상품별 결과가 회차마다 같은지를 요약한다.
- `--out` 파일에는 모델의 원래 출력이 남아, 무엇을 왜 버렸는지 볼 수 있다.
- `이름@접두어`는 `.env`의 `{접두어}_BASE_URL`(키는 `{접두어}_API_KEY`, 없으면 `OPENAI_API_KEY`)로 호출한다. 추론 모델은 `--default-temperature`로 temperature를 보내지 않는다.
