# 선택 에이전트 평가 기준

추출 에이전트 평가(`EXTRACTION_EVAL.md`)와 같은 방식으로 선택 에이전트를 잰다.
이 문서는 **정답을 어떻게 매기는지**까지만 다룬다. 측정 코드와 기준선은 다음 단계다.

## 0. 왜 재는가

추출 기준선 문서는 근거 없는 `false`를 치명(C1)으로 분류하면서 이유를 이렇게 적었다.

> 해당 특성을 "없음"으로 확정 → 심사 툴이 선택되지 않음 → 규제 미검출

**이 연결은 아직 측정된 적이 없다.** 툴이 실제로 누락되는지, 몇 건이나 누락되는지 모른다.
선택 에이전트를 같은 픽스처로 재면 추론이 측정값이 된다.

## 1. 두 가지 측정 모드

| 모드 | 입력 | 무엇을 보는가 |
|---|---|---|
| A | 사람이 매긴 정답 `Product` | 선택 에이전트 자체의 정확도 |
| B | 추출 에이전트가 만든 `Product` | 파이프라인 누적 오류 |

**모드 A 입력은 아직 다 정해지지 않았다.** 추출 정답표로 만들 텐데, 정답표에 `category`는 허용값
목록으로만 있고(여러 표현을 다 정답으로 인정하려는 목록이라 입력값 하나로는 못 쓴다) `intended_use`와
`listing_text`는 없다. 이걸 비워 두면 선택 에이전트는 원칙 2에 따라 식약을 선택하는 게 맞는데 정답은
미선택이라 C3로 잘못 센다(5절 null 처리). 2단계에서 세 값을 정한다.

**A와 B의 차이가 추출 품질이 선택에 미치는 영향이다.** 단, B에서만 생긴 C1(A에서는 선택했는데
B에서는 놓친 툴)을 전부 추출 탓으로 세면 안 된다.

예를 들어 정답은 `wireless_charging=true`인데 추출이 확신이 없어 `null`로 넘겼다고 하자.
A에서는 선택 에이전트가 전파를 선택하고, B에서는 `null`을 "없음"으로 보고 건너뛴다.
차이는 B에서 생겼지만 추출은 모른다고 정직하게 넘겼다(추출 채점으로는 C2). `null`을
"없음"으로 본 것은 선택 프롬프트 원칙 2("None은 없다가 아니다")를 어긴 선택의 잘못이다.

그래서 B에서만 생긴 C1은 그 툴의 판단 필드(4절 표)를 추출이 어떻게 넘겼는지로 나눠 센다.

| 정답 | 추출이 넘긴 값 | 누구 탓 | 이유 |
|---|---|---|---|
| `true` 또는 `null` | `false` | 추출 | 근거 없이 "없음"으로 확정했다. 추출 채점의 C1과 같은 오류다 |
| `true` | `null` | 선택 | 추출은 모른다고 넘겼다(추출 채점 C2). `null`을 "없음"으로 본 것은 원칙 2 위반이다 |
| `true` | `true` | 선택 | 추출은 맞게 넘겼는데 선택이 흔들렸다 |

판단 필드가 여러 개면 하나라도 추출 탓 행에 해당하는 필드가 있으면 추출 탓으로 센다. 그 `false`가
선택에게 "해당 없음"의 근거를 준 셈이기 때문이다.

`conflicts` 때문에 선택하는 경우(원칙 6)는 정답에 있는 충돌을 추출이 빠뜨렸으면
추출 탓이다. `power_bank` 전기가 이 경우다. 판단 필드가 전부 `null`이라 충돌이 선택의 유일한
근거다.

"추출이 선택에 미치는 영향"으로 보고하는 값은 이 중 **추출 탓만**이다. 선택 탓은 A의 오류와
함께 선택 에이전트의 문제로 센다. 통관은 거의 항상 선택하고 표시광고는 `listing_text`를 보므로
판단 필드가 없어 이 분류에서 뺀다.

## 2. 채점 규칙

선택 여부는 유보가 없다. 실행하거나 안 하거나 둘 중 하나다.

| 정답 \ 예측 | 선택함 | 미선택 |
|---|---|---|
| **선택해야 함** | 정답 | 🔴 **C1** |
| **미선택해야 함** | 🟠 C3 | 정답 |

- **C1**: 심사해야 할 도메인을 건너뛴다. 규제가 조용히 누락되므로 치명이다.
- **C3**: 불필요한 툴이 돈다. 비용과 지연이 늘어난다. 그 툴이 잘못된 판단을 내놓으면 최종 결과에
  들어가므로 판정이 틀릴 수도 있지만, 그건 툴이 틀린 것이라 여기서는 C1보다 가볍게 본다.

추출 채점표와 같은 비대칭이다. 선택 프롬프트 원칙 1("놓치는 것보다 과잉 선택이 낫다")과도
방향이 같다.

반복 실행·안정성 분류(안정정답 / 안정오답 / 불안정)는 추출 평가의 것을 그대로 쓴다.

## 3. 정답표 형식

`tests/eval_truth_selection/<픽스처>.json`. 추출 정답표와 같은 픽스처를 가리킨다.

```json
{
  "fixture": "wireless_shield_rfid.txt",
  "reviewed_by": "gityhb",
  "reviewed_at": "2026-09-28",
  "prompt_sha256": "a14ad31a…",
  "summary": "RFID 차단 지갑. 전파를 막는 기능과 주고받는 기능을 구분하는지 보는 케이스다.",
  "tools": {
    "radio_compliance": {
      "selected": true,
      "evidence": "제목 'RFID 차단'",
      "why_not_other": "wireless_shield=true다. 전파를 주고받지는 않으나 프롬프트가 wireless_shield도 선택 기준으로 규정한다."
    }
  }
}
```

**미선택 툴도 반드시 적는다.** 선택 에이전트가 미선택 사유까지 보고하므로, 정답표도 같은
규격이어야 "빠뜨린 것"과 "미선택으로 판단한 것"을 구분할 수 있다.

`why_not_other`를 필수로 두는 이유는 추출과 같다. 판단이 갈리는 지점에 근거가 없으면
나중에 정답 자체가 틀렸을 가능성을 걸러낼 수 없다.

**`prompt_sha256`은 추출 정답표에 없는 필드다.** 추출 정답은 페이지 사실이라 프롬프트와 무관하지만,
선택 정답은 선택 프롬프트의 규칙에서 나온다(4절). 프롬프트가 바뀌면 정답표가 옛 규칙 기준으로
조용히 남으므로, 정답을 매길 때의 `prompts/selection.md` 지문을 적는다. 지금 프롬프트와 다르면
`test_정답을_매긴_선택_프롬프트가_지금과_같다`가 실패한다. **선택 프롬프트를 고치면 정답표를
다시 검토하고 지문을 갱신해야 한다.** 지문은 줄바꿈을 LF로 맞춰 잰다(추출 러너와 같은 함수).

## 4. 툴별 판정 기준

선택 프롬프트의 기준을 그대로 따른다. 정답을 매길 때 추가로 정한 것만 적는다.

**이 정답은 "규제상 맞는 선택"이 아니라 "선택 프롬프트대로라면 해야 할 선택"이다.** 그래서 이
측정은 선택 에이전트가 자기 규칙을 지키는지와, 추출 오류가 그 규칙 적용을 얼마나 흐트러뜨리는지를
잰다. 프롬프트 규칙 자체가 틀린 것은 잡지 못한다.

실제로 기준이 갈리는 곳이 있다. 선택 프롬프트는 `wireless_shield=true`면 전파를 선택하라고 하지만,
검증 에이전트의 누락 검사는 전파 신호로 `wireless_comm`·`wireless_charging`만 본다
(`app/agents/verification.py`의 `_check_required_tools`). 이 정답표는 선택 프롬프트를 따라
`wireless_shield_rfid` 전파를 선택으로 매겼다.

선택 담당과 확인해 **선택 프롬프트 쪽을 고치기로 했다**(#188 리뷰). 선택 담당 설명으로는 서비스 구조
문서에 "RFID 차단은 전파를 막는 기능이라 대상이 아님"으로 되어 있고, 추출 스키마도 통신·충전·차폐를
일부러 나눠 두었다. 선택 프롬프트가 바뀌면 지문 테스트가
실패하므로, 그때 `wireless_shield_rfid` 전파 정답을 다시 본다.

판단 필드 중 `true`가 있으면 선택한다. `true`가 없고 `null`이 섞여 있으면 5절의 null 처리를 따른다.

| 도메인 | 정답을 매길 때 본 것 |
|---|---|
| 통관 | 해외 직구 수입품이면 선택. 원칙 3 그대로 |
| 전파 | `wireless_comm`·`wireless_charging`·`wireless_shield`. 제목의 "무선"이 코드리스를 뜻하면 근거로 쓰지 않는다 |
| 식약 | `food_contact`·`medical_claim`·`cosmetic_claim`. `skin_contact`는 단독으로 쓰지 않고 용도를 함께 본다 |
| 전기 | `electrical_powered`·`battery_included`·`battery_is_the_product`·`heating`. 관련 필드가 `false`여도 `conflicts`가 있으면 선택(원칙 6) |
| 어린이 | `for_children`이 확인되거나 연령 표기가 만 13세 이하를 포함하면 선택 |
| 표시광고 | 판매자가 쓴 상품 문구만 본다. 아래 제외 규칙 참고 |

## 5. 정해야 하는 것

표시광고 판정에서 세 가지를 정하고 정답을 매겼다. 선택 에이전트 담당과 확인했다(#188 리뷰).

**① 플랫폼 공통 문구를 제외했다.** Temu 페이지에는 "안전한 결제", "구매 보호",
"청소년 보호정책" 같은 문구가 상품과 무관하게 붙는다. 상품 광고로 보지 않았다.

**② 구매자 리뷰를 제외했다.** `wireless_shield_rfid`의 "효과는 100%입니다"는 리뷰 본문이다.
표시광고 규제 대상은 판매자의 표시·광고라고 보고 근거로 쓰지 않았다.

**③ 인증 표기는 실재 여부가 아니라 국내 인증으로 오인하게 쓰였는지로 본다.** 처음에는
`ali_sample`의 "CE-RoHS"가 실재하는 인증이라 표방으로 세지 않았는데, 선택 담당과 확인해 기준을
이렇게 정했다. 서비스 구조 문서에 "CE·FCC를 KC처럼 오인하게 하는 해외 인증 표기"가 표시광고 조치
대상으로 되어 있다는 것이 선택 담당 설명이다. 선택 프롬프트 예시 2의 `BPA Free`는 인증기관 없이 쓴
표방이라 성격이 다르고, 예시는 선택 담당이 이 기준으로 정리한다.

반대로 정했을 때 정답이 바뀌는지는 셋이 다르다.

| 기준 | 반대로 정하면 | 이유 |
|---|---|---|
| ② 리뷰 제외 | `wireless_shield_rfid` 표시광고가 선택으로 바뀐다 | "100%"는 프롬프트가 든 최상급 표현 예시 그대로다 |
| ① 플랫폼 문구 제외 | `power_bank` 표시광고가 바뀔 수 있다 | "보안 인증", "배송 보장"을 인증·보장 표방으로 읽을지에 달렸다 |
| ③ 인증 표기 | 바뀌지 않는다 | `ali_sample` 표시광고는 다른 문구로 이미 선택이다 |

①·②는 추출 쪽(#162)에서 리뷰와 플랫폼 문구를 판단 대상에서 빼기로 한 기준과 같고, 선택 담당도
동의했다. ③은 기존 3건에서는 정답에 영향이 없지만, 처음 보는 8건 중 2건(AA 충전지, LED 스탠드)의
표시광고를 가른다(6절). 선택 프롬프트 예시가 정리되면 지문 테스트가
실패하므로 그때 정답표를 다시 본다.

### 정답을 매기며 정한 null 처리

선택 프롬프트 원칙 2는 "None인 상태에서 미선택하려면 다른 필드에서 해당 없음의 근거가
있어야 한다"고 한다. 추출의 "상식으로 값을 확정하지 않는다"와 다른 규칙이다. 추출은 값을
정하는 단계라 페이지 근거만 보지만, 선택은 `category`·`intended_use` 같은 다른 필드를
근거로 쓸 수 있다.

- **다른 필드로 해당 없음이 확인되면 미선택.** 식약 3건은 `food_contact`가 null이지만
  카테고리(헤어드라이어·휴대폰 케이스·지갑)가 식품 접촉과 무관하다.
- **다른 필드로도 판단이 안 서면 선택.** `ali_sample` 전파는 "충전 거치대"가 무선충전인지
  카테고리로 알 수 없어 `wireless_charging`이 null로 남는다. `power_bank` 전파(MagSafe)도
  같은 이유로 선택이다.

처음 보는 상품 8건(#180 확인용)에도 같은 기준을 썼다.

- **전자기기는 무선 필드에 null이 하나라도 있으면 전파를 선택했다**(AA 충전지, 전기 모기채, LED 스탠드).
  LED 스탠드는 `wireless_comm=false`지만 `wireless_charging`이 null이다. 전지가 없어 무선으로 충전받을
  수는 없지만(스펙표 '배터리 포함 no'), `wireless_charging`은 무선으로 충전해 주는 기능(Qi 패드)도 포함한다.
  유선 전원은 충전 패드가 없다는 근거가 되지 않는다. 페이지가 충전 패드를 언급하지 않을 뿐 없다고 적지 않아 선택했다.
- 전기를 쓰지 않는 상품은 무선 필드가 null이어도 카테고리로 해당 없음을 확인했다(조리도구, 벨트, 괄사, 블록, 텀블러).
- 식약은 8건 모두 `food_contact`가 null이면 카테고리로 해당 없음을 확인했다.

## 6. 정답표 현황

| 묶음 | 픽스처 | 매긴 날 |
|---|---|---|
| 기존 3건 | `ali_sample`, `power_bank`, `wireless_shield_rfid` | 2026-09-28 |
| 처음 보는 8건 | 실리콘 조리도구, 자세교정 밴드, AA 충전지, LED 스탠드, 전기 모기채, 괄사 롤러, 블록 장난감, 스테인리스 텀블러 | 2026-10-05 |

8건에서 판단이 갈려 선택 담당 확인이 필요한 칸이다.

| 칸 | 매긴 값 | 갈리는 이유 |
