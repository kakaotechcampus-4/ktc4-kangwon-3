# 사용자 시나리오 끝단 평가 (추출 → 선택)

실제 테무·알리 상품 원문을 사용자가 붙여 넣는 그대로 넣고, 추출 → 선택까지 돌려
**걸리는 규제 심사(6개 Tool)를 빠짐없이 골랐는지**를 상품 단위로 센다.
추출 평가(`EXTRACTION_EVAL.md`)와 선택 평가(`SELECTION_EVAL.md`)가 단계 하나씩 본다면, 이 평가는 두 단계를 이어서 본다.
Tool 판정·검증·재질문은 아직 포함하지 않는다(법제처 API가 로컬에서 막혀 있다).

## 1. 무엇을 세나

- **빠뜨림**: 정답 `selected=true`인데 고르지 않음. 규제가 사용자에게 조용히 빠지므로 무겁게 본다.
- **과잉 선택**: 정답 `false`인데 고름. 비용·지연만 늘어 가볍게 본다.
- **무누락 상품**: N회 반복해 **모든 회차에서** 빠뜨림이 0인 상품. 한 회차라도 놓치면 실패다.
- 실패한 회차(추출·선택 예외)는 진단서가 나가지 않으므로 골라야 할 Tool을 전부 빠뜨린 것으로 센다.
- 빠뜨림 원인은 추출 정답이 있으면 나눈다: 추출이 false로 넘김 / 선택이 null을 없음으로 봄 / 선택이 근거를 보고도 놓침 /
  글 입력에 근거 없음(정답 근거가 상세 이미지·알리 설명 글에만 있음, 정답의 `image_only`).

채점: `app/eval/scenario_scoring.py`, 러너: `app/eval/scenario_runner.py`. 둘 다 LLM 없이 테스트된다.

## 2. 데이터

| 무엇 | 위치 |
|---|---|
| 선택 정답 (개발 50, 홀드아웃 15) | `tests/eval_truth_scenario/dev/`, `tests/eval_truth_scenario/holdout/` |
| 상품 원문 (글) | [팀 노션](https://app.notion.com/p/ZIP-3f15a820b2b88076ba5fd83f164adc4f) `scenario_raw_text.zip` |
| 상세 이미지 (정답 근거 확인용, 실행엔 불필요) | 용량(140MB) 때문에 노션에 없음. 필요하면 gityhb에게 요청 |

- 저장소가 public이라 상용 페이지 원문은 올리지 않는다(`tests/fixtures/README.md`). zip을 `ai/tests/fixtures/_raw/`에 그대로 풀고,
  zip 안 `MANIFEST_scenario.txt`의 지문(줄바꿈을 LF로 맞춘 SHA-256 앞 12자)으로 같은 원문인지 확인한다.
- 풀면 `strat_NN/`(개발), `holdout_scenario/holdout_NN/`(홀드아웃), `truth_drafts/`(개발 50의 추출 정답 초안, **미확정**, 원인 분류용),
  `scenario_truth/results/`(2026-11-05 측정 결과, 재채점용)가 생긴다.
- 상품 폴더마다 `text.txt`(더보기를 펼친 뒤 Ctrl+A, 주 입력), `text_as_pasted.txt`(펼치기 전, 보조), 알리는 `description.txt`(상세 설명 글)가 있다.
- 개발 50은 카테고리를 나눠 고른 표본이고 추출 규칙을 다듬는 데 썼다. **발표 숫자는 홀드아웃 15로만 낸다.**
  홀드아웃은 프롬프트·규칙을 고치는 동안 열지 않는다.

## 3. 실행

```bash
cd ai
# 개발 50, 펼친 글, 3회
python -m app.eval.scenario_runner --truth-dir tests/eval_truth_scenario/dev --raw-dir tests/fixtures/_raw \
    --extraction-truth-dir tests/fixtures/_raw/truth_drafts --runs 3 --report dev_expanded.md --title "개발 (펼친 글)"
# 홀드아웃 15, 펼치기 전 글
python -m app.eval.scenario_runner --truth-dir tests/eval_truth_scenario/holdout --raw-dir tests/fixtures/_raw/holdout_scenario \
    --input-file text_as_pasted.txt --runs 3 --report holdout_pasted.md --title "홀드아웃 (펼치기 전 글)"
# 저장된 결과 재채점 (모델 호출 없음). 결과 JSON의 정답 경로는 측정한 PC 기준이라 --truth-dir로 다시 가리킨다
python -m app.eval.scenario_runner --rescore tests/fixtures/_raw/scenario_truth/results/scenario-20261105-140049.json \
    --truth-dir tests/eval_truth_scenario/holdout --report again.md --title "홀드아웃 (펼친 글)"
```

- 상품마다 추출 N회, 추출 결과마다 선택 1회. 실패한 회차는 `--retries`(기본 2)번 다시 시도한다.
- 원문이 하나라도 없거나 정답 형식이 깨졌으면 모델을 만들기 전에 멈춘다. `--extraction-truth-dir`가 없는 폴더여도 멈춘다.
- 원문은 `--raw-dir`로 직접 가리킨다. **워크트리 안에 `_raw`로 가는 링크(정션)를 만들지 않는다.**
  `git worktree remove`가 링크를 따라가 원본을 지운 적이 있다.
- 결과는 `logs/eval/scenario-<시각>.json`에 저장된다. 4개 측정(표본 2 × 입력 2, 3회)은 mini 기준 수십 분 걸린다.

## 4. 정답 기준

정답은 "이 상품의 **실제 사실**(판매자 제목·스펙표·상세 글·상세 이미지 전부)에 선택 프롬프트 기준을 적용하면 골라야 하는 Tool"이다.
기존 선택 정답은 추출 결과를 받았을 때의 정답이지만, 이 평가는 끝단이라 **추출이 놓친 사실도 정답에 들어간다.**
초안을 만들고 gityhb가 65개 전부 확정했다(2026-11-05). 추출 결과·모델 출력을 보고 쓰지 않았다.

| Tool | true 기준 |
|---|---|
| 통관 | 해외 직구 수입품. 원산지 국내·국내 사업자·국내 발송이 명시되면 false (개발 6·30) |
| 전파 | 무선 통신·무선충전·전파 차폐(RFID 차단) 중 하나. 무선 기능 없는 유선 전자기기는 false (아래 한계) |
| 식약 | 음식 접촉·의료 효능 표방·미용 효과 표방. 피부 접촉은 용도로 본다: 귓구멍·점막에 넣는 용도(인이어 이어폰, 코털 트리머, 칫솔)는 true, 손목·손에 닿는 용도는 false |
| 전기 | 전기 구동·전지 포함·전지 자체·발열. 정격·전압·mAh 표기가 있으면 true |
| 어린이 | 연령·어린이 대상 표기, 또는 학용품·완구. 어린이도 쓸 수 있다는 것만으로는 false |
| 표시광고 | 판매자 문구에 효능 표방 / 최상급·절대 표현 / 미검증 인증(해외 인증 표기 포함) / 의료·미용 주장 / 과장 수치 중 하나가 **분명히** 있을 때. "미끄럼 방지", "친환경", "논스틱", "고속" 같은 기능·사양 설명은 false. 리뷰·쇼핑몰 공통 문구는 근거 아님 |

애매하면 true로 두고 `notes`에 "애매"라고 적었다. false는 "어떤 사실로 해당 없음이 확인되는지"를 `evidence`에 적었다.

## 5. 결과 (2026-11-05)

측정 조건: gpt-4.1-mini(운영 기본 프로필), 추출은 #580 브랜치, 선택은 #588 반영 전, 3회 반복. 실패 회차 0.

| 표본 | 입력 | 6개 Tool 무누락 | 표시광고 빼고 무누락 |
|---|---|---|---|
| **홀드아웃 15** | 펼친 글 | 7/15 | **12/15** |
| 홀드아웃 15 | 펼치기 전 글 | 7/15 | 12/15 |
| 개발 50 | 펼친 글 | 17/50 | 46/50 |
| 개발 50 | 펼치기 전 글 | 18/50 | 47/50 |

- 빠뜨림 대부분은 표시광고였다. 추출이 문구를 판매 문구 목록에 넘겼는데도 선택이 고르지 않았고, 선택이 표시광고를 고른 회차는 18%(72/390)였다.
  그래서 표시광고를 항상 실행하도록 바꿨다(#588). 바꾼 뒤 숫자는 develop 기준으로 다시 잰다.
- 표시광고를 빼고 남은 빠뜨림: 에어프라이어 식약(음식 접촉), 무드등 식약("수면 보조" 표방), 학교용 펜 어린이(학용품),
  개발의 마사지기 3개 식약(추출이 효능 칸을 null로 둔 회차에서 선택이 null을 없음으로 봄).
- 펼친 글과 펼치기 전 글의 끝단 차이는 작았다. 선택이 "모름"이면 고르는 쪽이라 추출의 모름 증가가 빠뜨림으로 잘 이어지지 않는다.

## 6. 한계

- **유선 전자파적합성은 보지 않는다.** 무선 기능 없는 유선 전기제품도 전파법상 적합성평가 대상일 수 있지만 전파 Tool은 무선 기기만 본다
  (`RADIO_TOOL.md`). 실제 예: 개발 33번 핫팩 겸 보조배터리가 방송통신기자재 적합성평가 번호를 달고 있다.
- 진단서 끝까지(Tool 판정·검증·재질문)는 아직 재지 않았다. 배포 서버에서 홀드아웃으로 잴 예정이다.
- 정답은 한 사람이 확정했다. 표시광고·식약 경계는 사람마다 갈릴 수 있다.
- 입력에 이미지를 넣지 않는다. 근거가 이미지에만 있는 빠뜨림은 '글 입력에 근거 없음'으로 따로 센다.
