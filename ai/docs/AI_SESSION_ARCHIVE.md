# 진단 세션 보관·복원 (#565)

진단 세션은 메모리(`sessions/store.py`)에서 돌고, 재시작 때 되살릴 세션만 AI DB에 같이 보관한다.
배포 때 실행 중인 진단은 drain이 끝까지 돌리고(`AI_LOGGING.md`), 아직 시작 전이거나 답을 기다리는 세션은 이 보관으로 지킨다.

`DATABASE_URL`이 없으면 보관하지 않고 메모리에만 둔다(재시작 때 사라짐).

## 무엇을 보관하나

상태별 보관 여부는 `sessions/transitions.py`의 `STATUS_TRAITS.archived` 한 곳에서 정한다.

| 상태 | 보관 | 재시작 때 |
|---|---|---|
| 접수 (대기, 첫 진단·재진단) | O | 같은 runId로 다시 실행. 이 실행으로 BE에 보낸 콜백이 없어 BE는 차이를 모름. 접수 시각은 그대로라 내려가 있는 동안 최대 시간(600초)을 넘겼으면 실행하지 않고 `AI_TIMEOUT`(재시도 가능) 실패 콜백 |
| 실행 중 | O | drain 없이 끊긴 실행(메모리 부족·재부팅 등). 다시 돌리지 않고 바로 `AI_TIMEOUT`(재시도 가능) 실패 콜백 |
| 답변 대기 | O | 그대로 되살려 답이 오면 재진단 (보관 시간 24시간은 질문을 보낸 시각부터 그대로) |
| 완료·실패 | X | 결과 콜백이 이미 나감 |
| 개발용(샌드박스) 진단 | X | 콜백 없는 확인용 |

## 표 `diagnosis_sessions`

| 칸 | 내용 |
|---|---|
| `product_id` (키) | 상품 ID. 상품당 한 행이라 새 접수·재접수는 덮어씀 |
| `status`, `run_type` | 상태, 실행 종류 |
| `updated_at` | 세션 마지막 변경 시각 |
| `session` (jsonb) | `DiagnosisSession` 전체 (원래 입력, 실행 ID, 질문·답변, 회차, 이전 결과, 접수 시각). 복원은 이 값만으로 함 |
| `fetched_at` | 마지막으로 쓴 시각 |

- 표는 기동 때 `init_db`가 만든다(있으면 건너뜀).
- 복원 때 지금 세션 모양과 안 맞는 행(배포로 모양이 바뀐 옛 행)은 경고 후 지운다.

## 언제 쓰고 지우나

| 일 | DB |
|---|---|
| 접수, 실행 시작, 질문으로 끝남, 재접수 | 저장 (덮어쓰기) |
| 단계 변경, Tool 진행 | 안 씀 (상태가 그대로라 복원에 필요 없음) |
| 완료, 실패 (시간 초과 포함) | 삭제 |
| 답변 대기 보관 시간 지남 | 삭제 (세션 정리 루프) |

- 세션 저장소 잠금 안에서 써서 같은 세션의 저장·삭제 순서가 뒤바뀌지 않는다.
- DB를 못 쓰면 경고만 남기고 진단은 메모리로 계속 돈다. 실패 뒤 60초는 DB를 건너뛴다(`DbSkip`).
  건너뛴 동안의 변경은 DB에 안 남아 복원 때 이미 끝난 세션이 되살아날 수 있지만, BE가 이미 받은 결과·실패로 보고 무시한다.

## 기동 순서 (`app.main`)

DB 준비(`init_db`) → 세션 관리자·콜백·지표 구독 연결 → 보관된 세션 복원 → 요청 받기 시작.
구독을 다 붙인 뒤 복원해 되살린 세션의 결과·실패도 콜백으로 나간다.

## BE와 맞는지 (BE 코드 확인)

- 실패 콜백은 BE가 순번(`sequence`)을 보지 않고 runId로만 확인한다. 재시작 뒤 순번 1로 보내도 반영된다.
- 순번은 진행 콜백의 단계별 순서에만 쓰인다. 다시 실행하는 대기 세션은 이 실행으로 보낸 콜백이 없어 1부터 시작해도 맞는다.
- BE 멈춘 진단 정리(15분)가 먼저 실패 처리한 뒤 늦게 결과가 오면, BE가 이미 실패로 보고 무시(실패 콜백)하거나 409로 거절(결과 콜백)한다. 발신함은 409를 재시도 없이 버린다.
