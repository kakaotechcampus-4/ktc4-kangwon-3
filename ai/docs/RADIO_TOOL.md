# 전파 Tool — 조건 추출 · 대상기자재 조회 · 기자재 선택 (#297)

## 파일 구성

| 위치 | 내용 |
|---|---|
| `app/tools/radio/tool.py` | `RadioTool` 흐름 (조건 추출 → 조회 → 규칙 → 선택 → 결과 조립) |
| `app/tools/radio/rules.py` | 주파수 정규화, 평가유형별 근거 항, 판매 방식별 안내 문구 |
| `app/tools/radio/search.py` | 조회 인터페이스 `RadioItemSearch`, `LawApiItemSearch`, `DatabaseItemSearch`(스텁) |
| `app/tools/radio/evidence.py` | 전파법 제58조의2, 고시 별표 1(1~10절), 시행령 별표 6의2 읽기 |
| `app/tools/common/` | 규제 Tool 공용 (어린이제품 Tool과 같이 씀) |
| `app/schemas/radio.py`, `app/prompts/radio/facts.md`·`review.md` | 모델 입출력 |
| `tests/tools/radio/` | 단위 테스트와 법제처 Fake(`conftest.py`) |
| `tests/fixtures/radio_law/` | 실제 법제처 응답 원문 |

`app.tools.registry`는 그대로 `from .radio import RadioTool`로 가져온다.

## 흐름

```text
Product (추출 에이전트 결과)
→ ① 모델 조건 추출   제품 종류·무선 기능·주파수·출력·용도 + 상품 원문 인용, 조회어                (prompts/radio/facts.md)
                     대상기자재 분류명 목록("분류 > 세부 분류", 209개)을 주고 조회어를 그 안에서 고르게 한다
→ ③ 코드 규칙        무선 기능 원문 근거가 없으면 여기서 끝(후보 없음) · 주파수 표기를 MHz로 정규화
→ ② 코드 조회        고시 별표 1(1~10절, 230행) 중 비슷한 상위 8개
→ ④ 모델 기자재 선택 후보 행 중 맞는 행 + 이유 + 해당 여부(applies). 해당 없음·대조 안 되는 선택을 거른 뒤 최대 3개                  (prompts/radio/review.md)
→ ⑤ 코드 결과 조립   근거(행 원문·전파법 제58조의2 해당 항·시행령 별표 6의2) + 판매 방식별 할 일
```

- 대상기자재 표는 상품명이 아니라 무선 기술·용도로 분류된다(블루투스 이어폰 → "특정소출력무선기기 > 무선데이터통신시스템용무선기기"). 동의어 사전 대신 법령에서 읽은 분류명 목록을 조건 추출 모델에 준다.
- **적합인증·적합등록·자기적합확인 구분은 모델이 아니라 행의 ○ 표시**를 그대로 쓴다.

## 코드 규칙

| 규칙 | 근거 | 동작 |
|---|---|---|
| 무선 기능 | 이슈 #297 범위(무선 기기) | 상품 원문에 무선 기능 인용이 없으면 후보를 내지 않고 무선 기능을 묻는다. 비대상 판단이 아니다. 유선 전자파적합성(11절)은 범위 밖 |
| 주파수 | 고시 별표 1 행 이름의 대역 | 원문 표기(2.4GHz, 5150∼5350㎒, 125kHz 등)를 MHz로 바꿔 행 대역과 함께 모델에 준다. 주파수 조건뿐 아니라 무선 기능 값 안의 표기("Bluetooth 5.0 (2.4GHz)")도 읽는다. 대역으로 행을 빼지는 않는다(상품 표기가 대략값이라). 판단을 바꾸지 않아 질문하지 않고, 없으면 가정으로 남긴다 |
| 평가유형 → 근거 항 | 전파법 제58조의2 | 적합인증 ②, 적합등록 ③, 자기적합확인 ④ |
| 개인 사용 반입 면제 | 시행령 별표 6의2 자목 | 판매 안내에 "개인 사용 목적 1대 반입은 면제 대상일 수 있음(1년 이내 판매 시 제외), 구매대행 해당 여부는 확인 필요"로 조건부 표기 |

| 역할 | 담당 |
|---|---|
| 상품 조건 값과 원문 인용, 조회어 | 모델 |
| 인용 대조, 무선 기능 규칙, 주파수 정규화, 조회, 평가유형, 근거 연결, 결과 상태 | 코드 |
| 후보 행 중 맞는 행 고르기와 이유 | 모델 |
| 확정 판단(`REQUIRED`/`NOT_REQUIRED`) | 사람이 검토한 코드 규칙만. **아직 없음** |

## 대상기자재 조회 (`app/tools/radio/search.py`)

- `RadioItemSearch.catalog()`(분류명 목록), `search(terms, top_k) -> RadioCandidates`로 추상화했다.
- `LawApiItemSearch` (현재): 법제처 API로 전파법·시행령·고시를 받아(요청 6회, 약 2초) 기준일별로 캐시한다(6시간).
  - 고시 별표 1의 1~10절(무선설비 기기)만 읽는다. 11절(전자파장해 기기)은 범위 밖이다.
  - 칸 줄이 어긋나도 행 오른쪽 끝 10칸(적용분야 5, 평가유형 3, 기기부호, 기타사항)은 순서가 고정이라 오른쪽부터 센다.
  - 바깥 분류가 여러 행에 걸치고 이름이 부분 가로선 줄에 이어지는 것("라.특정소출력 / 무선기기")을 이어 붙인다. 삭제된 행은 뺀다.
  - 검사: 1~10절이 모두 있는지, 기기부호가 비거나 겹치지 않는지. 2026-10-14 기준 230행, 행마다 평가유형 1개.
  - 절 끝 비고(예: 5절 전자파흡수율 적용 조건)는 절별로 모아 선택 모델에 같이 준다.
  - 고시는 2026-11-06 시행본이 미리 조회된다. 기준일에 시행 중인 버전만 쓴다.
- `DatabaseItemSearch` (스텁): 파싱 에이전트가 고시 별표 1을 DB에 넣으면 쓸 자리다. 칸 정의는 "어린이·전파 품목표 칸 정의" 문서를 따른다.

## 결과

- 선택된 행: `POSSIBLY_REQUIRED`, subject `"{평가유형} 대상기자재 후보 — {기자재명}"`. 근거는 고시 별표 1 행 원문, 전파법 제58조의2 해당 항, 시행령 별표 6의2 자목.
- `required_actions`: 행마다 "사입·수입 판매: 적합성평가 받은 제품인지 KC 번호로 확인", "구매대행: 개인 사용 1대 면제 가능성, 해당 여부 확인 필요"(면제 목을 찾았을 때만). 각 판단의 `requirements`에도 그 행의 안내를 연결한다(재실행에서 판단이 빠지면 ToolExecutor가 그 할 일만 지움).
- 질문(`missing_information`)은 판단을 바꾸는 조건(제품 종류·무선 기능)만. 그 밖에 선택 모델이 요청한 조건은 판단의 assumptions에 "확인이 더 필요"로 남긴다(#341과 같은 기준).
- 추출 단계가 표시한 상품 모순(`Product.conflicts`)은 조회를 막지 않고 assumptions에만 남긴다. 제품 종류가 여러 값이면 충돌로 보지 않고 모두 조회어로 쓴다(#341과 같음).
- `RadioAssessment`: `wireless_features`(원문), `frequency_bands`(정규화), `certification_type`(선택한 행들의 평가유형), `conformity_assessment_required=None`.
- 모델 출력 중 대조되지 않는 항목은 그 항목만 버린다. `applies=false` 선택도 버린다.
- `query`: `dropped_facts`, `dropped_candidates`, `not_applicable`, `over_limit`(상한을 넘은 유효 선택), `search_terms`, `frequency_bands`, `candidate_items`, `selected_items`, `assessment_types`, `documents`.
- 모델 호출·구조화 출력 실패, 법령 조회 오류는 `RadioToolError`로 전파한다. 근거 버전을 확인하지 못하면 정보 부족(SUCCESS)으로 끝낸다.
- 사용량은 `radio-facts`, `radio-review`로 기록한다.

## 검증

- 단위 테스트(모델·API는 Fake, 법령은 실제 법제처 응답 픽스처): `ai/`에서

  ```bash
  uv run pytest tests/tools/radio tests/tools/test_registry.py tests/prompts -q
  ```
- 대표 결과를 실제 `VerificationAgent().verify_rules()`에 넣어 재실행 요청·이슈가 없는지 테스트로 확인한다.
- 2026-10-14 실제 모델(gpt-4.1-mini) 확인: 블루투스 이어폰(2.4GHz) → 무선데이터통신시스템용(적합인증),
  Wi-Fi 홈캠(2.4/5GHz) → 무선랜 5GHz 대역 + 무선데이터통신(적합인증), RC 자동차 → 무선조정용(적합인증),
  유선 키보드 → 무선 기능 없음(후보 없음). 상품당 2~6초.
