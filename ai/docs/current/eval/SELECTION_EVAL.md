# 선택 에이전트 평가

선택 에이전트가 추출 결과를 보고 Tool을 올바르게 선택하는지, 그리고 추출 오류가 선택에 미치는 영향이 얼마인지를 측정한다. 실행 결과 저장, 측정 조건 기록, 평가셋 구분 등 공통 규칙은 [EVAL_COMMON.md](EVAL_COMMON.md), 반복 실행·안정성 분류는 [EXTRACTION_EVAL.md](EXTRACTION_EVAL.md) 5장을 참고한다.

## 1. 두 가지 측정 모드

| 모드 | 입력 | 확인 대상 |
|---|---|---|
| A | 추출 결과에서 **boolean 15개만 정답값으로 바꾼** `Product` | 선택 에이전트 자체의 정확도 |
| B | 추출 에이전트가 생성한 `Product` 그대로 | 파이프라인 누적 오류 |

**모드 A는 정답 `Product`를 통째로 사용하지 않는다.** 추출 정답표의 `category`는 허용값 목록으로만 있어 입력값 하나로 사용할 수 없고, `intended_use`는 없으며, `listing_text`는 일부 정답표에만 일부 문구가 있다. 이 값들을 사람이 별도로 작성하는 대신 같은 추출 결과를 A·B로 두 번 사용하고, A에서는 boolean만 정답으로 바꾼다. 두 입력은 boolean만 다르므로 A와 B의 차이가 그대로 "추출의 boolean 오류가 선택에 미친 영향"이 된다.

그러므로 A의 글자 필드는 추출 결과이며, 추출이 `listing_text`에서 문구를 누락한 경우는 A에서도 놓치고 추출 탓으로 분류되지 않는다.

**B에서만 생긴 C1(A에서는 선택하였으나 B에서는 놓친 Tool)을 전부 추출 탓으로 세지 않는다.** 예를 들어 정답은 `wireless_charging=true`인데 추출이 확신이 없어 `null`로 넘겼다고 하자. A에서는 선택 에이전트가 전파를 선택하고, B에서는 `null`을 "없음"으로 보고 건너뛴다. 차이는 B에서 생겼지만 추출은 모른다고 정직하게 넘겼으며(추출 채점으로는 C2), `null`을 "없음"으로 본 것은 선택 프롬프트 원칙 2("None은 없다가 아니다")를 위반한 선택의 잘못이다.

그러므로 B에서만 생긴 C1은 그 Tool의 판단 필드(4장 표)를 추출이 어떻게 넘겼는지로 나누어 센다.

| 정답 | 추출이 넘긴 값 | 원인 | 이유 |
|---|---|---|---|
| `true` 또는 `null` | `false` | 추출 | 근거 없이 "없음"으로 확정하였다. 추출 채점의 C1과 같은 오류이다 |
| `true` | `null` | 선택(원칙 2) | 추출은 모른다고 넘겼다(추출 채점 C2). `null`을 "없음"으로 본 것은 원칙 2 위반이다 |
| 판단 필드는 정답과 같음 | 다른 boolean이 정답과 다름 | 추출(다른 필드) | A·B 입력은 boolean만 다르므로 차이는 나머지 boolean에서 온다 |
| 판단 필드는 정답과 같음 | boolean 전부 정답과 같음 | 선택(흔들림) | 입력이 A와 동일한데 결과만 다르다 |

- 판단 필드가 여러 개이면 하나라도 추출 원인 행에 해당하는 필드가 있으면 추출 탓으로 센다. 그 `false`가 선택에 "해당 없음"의 근거를 제공한 것이기 때문이다.
- 판단 필드가 아닌 필드의 근거 없는 확정도 선택을 흔들 수 있으므로 "추출(다른 필드)" 행을 둔다.
- `conflicts` 때문에 선택하는 경우(원칙 6)는 정답에 있는 충돌을 추출이 누락하였으면 추출 탓이다.
- "추출이 선택에 미치는 영향"으로 보고하는 값은 이 중 **추출 원인만**이다. 선택 원인은 A의 오류와 함께 선택 에이전트의 문제로 센다. 통관은 거의 항상 선택하고 표시·광고는 `listing_text`를 보므로, 판단 필드가 없어 이 분류에서 제외한다.

## 2. 채점 규칙

선택 여부에는 유보가 없다. 실행하거나 실행하지 않거나 둘 중 하나이다.

| 정답 \ 예측 | 선택함 | 미선택 |
|---|---|---|
| **선택해야 함** | 정답 | **C1** |
| **미선택해야 함** | C3 | 정답 |

- **C1**: 심사해야 할 분야를 건너뛴다. 규제가 드러나지 않게 누락되므로 치명적이다.
- **C3**: 불필요한 Tool이 실행되어 비용과 지연이 늘어난다. 그 Tool이 잘못된 판단을 출력하면 최종 결과에 포함되어 판정이 틀릴 수도 있으나, 이는 Tool의 오류이므로 이 평가에서는 C1보다 가볍게 본다.

추출 채점표와 같은 비대칭이며, 선택 프롬프트 원칙 1("놓치는 것보다 과잉 선택이 낫다")과도 방향이 같다. 채점은 Tool 하나의 결정 하나 단위로 센다.

## 3. 정답표 형식

정답표는 `tests/eval_truth_selection/<픽스처>.json`이며, 추출 정답표와 같은 픽스처를 가리킨다.

```json
{
  "fixture": "wireless_shield_rfid.txt",
  "reviewed_by": "gityhb",
  "reviewed_at": "2026-09-28",
  "prompt_sha256": "c24174f95164…",
  "summary": "RFID 차단 지갑. 전파를 막는 기능과 주고받는 기능을 구분하는지 보는 케이스다.",
  "tools": {
    "radio_compliance": {
      "selected": true,
      "evidence": "제목 'RFID 차단'",
      "why_not_other": "wireless_shield=true다. 전파를 주고받지는 않으나 프롬프트가 wireless_shield도 선택 기준으로 규정한다."
    }
  }
}
```

- **미선택 Tool도 반드시 적는다.** 선택 에이전트가 미선택 사유까지 보고하므로, 정답표도 같은 규격이어야 "누락한 것"과 "미선택으로 판단한 것"을 구분할 수 있다.
- `why_not_other`를 필수로 두는 이유는 추출과 같다. 판단이 갈리는 지점에 근거가 없으면 정답 자체가 틀렸을 가능성을 걸러낼 수 없다.
- **`prompt_sha256`은 추출 정답표에 없는 필드이다.** 추출 정답은 페이지 사실이므로 프롬프트와 무관하지만, 선택 정답은 선택 프롬프트의 규칙에서 나온다(4장). 프롬프트가 바뀌면 정답표가 이전 규칙 기준으로 남으므로, 정답을 매길 때의 `agents/selection/prompt.md` 지문을 기록한다. 지문은 줄바꿈을 LF로 통일하여 계산한다(추출 러너와 같은 함수). **선택 프롬프트를 수정하면 정답표를 다시 검토하고 지문을 갱신한다.**

정답표는 `tests/eval/test_truth_selection.py`가 모델 호출 없이 검사한다.

| 검사 | 내용 |
|---|---|
| Tool 구성 | 6개 Tool이 각각 한 번씩 있으며, 같은 Tool이 두 번 적히면 읽을 때 실패 |
| 값 형식 | 선택 여부가 참·거짓으로만 적혀 있음 |
| 근거 | 사람의 판단 근거(`evidence`·`why_not_other`), 픽스처와 검토자가 적혀 있음 |
| 프롬프트 지문 | 정답을 매긴 선택 프롬프트가 현재와 같음(`test_정답을_매긴_선택_프롬프트가_지금과_같다`) |
| 픽스처 | 추출 정답표와 같은 픽스처를 가리킴 |

## 4. Tool별 판정 기준

선택 프롬프트의 기준을 그대로 적용한다. 정답을 매길 때 추가로 정한 것만 기술한다.

**이 정답은 "규제상 맞는 선택"이 아니라 "선택 프롬프트대로라면 해야 할 선택"이다.** 그러므로 이 측정은 선택 에이전트가 자기 규칙을 지키는지와, 추출 오류가 그 규칙 적용을 얼마나 흐트러뜨리는지를 측정한다. 프롬프트 규칙 자체가 틀린 것은 검출하지 못한다.

판단 필드 중 `true`가 있으면 선택한다. `true`가 없고 `null`이 포함되어 있으면 6장의 null 처리를 적용한다.

| 분야 | 정답을 매길 때 확인한 것 |
|---|---|
| 통관 | 해외 직구 수입품이면 선택. 원칙 3 그대로 |
| 전파 | `wireless_comm`·`wireless_charging`·`wireless_shield`. 제목의 "무선"이 코드리스를 뜻하면 근거로 사용하지 않는다 |
| 식약 | `food_contact`·`medical_claim`·`cosmetic_claim`. `skin_contact`는 단독으로 사용하지 않고 용도를 함께 확인한다 |
| 전기 | `electrical_powered`·`battery_included`·`battery_is_the_product`·`heating`. 관련 필드가 `false`여도 `conflicts`가 있으면 선택(원칙 6) |
| 어린이 | `for_children`이 확인되거나 연령 표기가 만 13세 이하를 포함하면 선택 |
| 표시·광고 | 판매자가 작성한 상품 문구만 확인한다. 5장의 기준 참고 |

- 선택 프롬프트는 `wireless_shield=true`이면 전파를 선택하도록 규정하지만, 검증 에이전트의 누락 검사는 전파 신호로 `wireless_comm`·`wireless_charging`만 확인한다(`app/agents/verification/rules.py`의 `check_required_tools`). 정답표는 선택 프롬프트를 기준으로 `wireless_shield_rfid`의 전파를 선택으로 매겼다.
- 선택 에이전트는 모델 판단과 관계없이 표시·광고를 항상 선택으로 고정한다(`app/agents/selection/agent.py`의 `ALWAYS_RUN_TOOLS`). 그러므로 `--selector llm`으로 측정하면 표시·광고 미선택 정답은 항상 C3로 집계되며, 표시·광고 칸은 모델의 판단을 측정하지 않는다. 판단 선택 에이전트(`--selector decision`)는 표시·광고도 판단 모델의 질문으로 정한다.

## 5. 표시·광고 판정 기준

| 기준 | 내용 |
|---|---|
| 플랫폼 공통 문구 제외 | Temu의 "안전한 결제", "구매 보호", "청소년 보호정책"처럼 상품과 무관하게 표시되는 문구는 상품 광고로 보지 않는다 |
| 구매자 리뷰 제외 | 표시·광고 규제 대상은 판매자의 표시·광고이므로 리뷰 본문(예: `wireless_shield_rfid`의 "효과는 100%입니다")은 근거로 사용하지 않는다 |
| 인증 표기 | 실재 여부가 아니라 국내 인증으로 오인하게 사용되었는지로 판단한다. 스펙표에 해외 인증(CE·FCC·RoHS) 이름을 나열한 것만으로는 표방이 아니다 |
| 가게 단위 소개 제외 | Temu 브랜드 소개("보증: 최고의 품질")처럼 가게의 모든 상품에 표시되는 문구는 이 상품의 표시·광고로 보지 않는다 |
| AI 상품 요약 제외 | AliExpress의 "AI 상품 요약"은 페이지가 판매자 의견이 아니라고 밝히므로 근거로 사용하지 않는다 |

플랫폼 문구·리뷰 제외는 추출 평가에서 두 문구를 `listing_text`에서 제외하는 기준과 같다([EXTRACTION_EVAL.md](EXTRACTION_EVAL.md) 2.3절). 표시·광고 Tool 자체의 문구 판정은 [ADVERTISING_TOOL.md](../tools/ADVERTISING_TOOL.md)를 참고한다.

## 6. null 처리

선택 프롬프트 원칙 2는 "None인 상태에서 미선택하려면 다른 필드에서 해당 없음의 근거가 있어야 한다"고 규정한다. 추출의 "상식으로 값을 확정하지 않는다"와 다른 규칙이다. 추출은 값을 정하는 단계이므로 페이지 근거만 보지만, 선택은 `category`·`intended_use` 같은 다른 필드를 근거로 사용할 수 있다.

- **다른 필드로 해당 없음이 확인되면 미선택한다.** 예: `food_contact`가 null이지만 카테고리(헤어드라이어·휴대폰 케이스·지갑)가 식품 접촉과 무관한 경우
- **다른 필드로도 판단할 수 없으면 선택한다.** 예: `ali_sample`의 "충전 거치대"가 무선충전인지 카테고리로 알 수 없어 `wireless_charging`이 null로 남는 경우
- **전자기기는 무선 필드에 null이 하나라도 있으면 전파를 선택한다.** `wireless_charging`은 무선으로 충전해 주는 기능(Qi 패드)도 포함하므로, 유선 전원은 충전 패드가 없다는 근거가 되지 않는다.
- 전기를 사용하지 않는 상품은 무선 필드가 null이어도 카테고리로 해당 없음을 확인한다.

다음 칸은 판단이 갈려 선택 담당과 확인한 정답이다.

| 칸 | 정답 | 근거 |
|---|---|---|
| AA 충전지·LED 스탠드 표시·광고 | 미선택 | 판매자 문구는 규격뿐이고 스펙표에 해외 인증만 나열되어 있어 5장 인증 표기 기준으로 표방이 아니다 |
| 전기 모기채 표시·광고 | 선택 | 제목 '고효율 수직형 해충 퇴치기'는 실증이 필요한 성능 주장이며, 애매하면 선택하는 원칙 1에도 해당한다 |
| 전기 모기채 전파 | 선택 | 방송통신기자재등의 적합성평가에 관한 고시 별표 1의 '10) 해충퇴치기류'(전격살충기 등)에 해당하여 무선 기능이 없어도 적합성평가 대상이다 |
| AA 충전지·LED 스탠드 전파 | 선택 | 전자기기에 무선 필드 null이 있어 원칙 1·2로 선택하였다. LED 스탠드는 같은 별표의 조명기기류 8)에 단순 조명 제외 조항이 있어 가장 판단이 약한 칸이다 |
| 실리콘 조리도구 표시·광고 | 선택 | 상품 설명 '요리와 베이킹에 완벽'은 프롬프트의 절대적 표현 유형이다. 브랜드 소개 '최고의 품질'은 가게 단위 소개로 근거에서 제외하였다 |

## 7. 실행

```bash
python -m app.eval.selection_runner --extraction-log logs/eval/<추출 결과>.json --runs 5
python -m app.eval.selection_runner --extraction-log A.json --extraction-log B.json --runs 10
python -m app.eval.selection_runner --extraction-log A.json --selector decision --decision-profile luna
python -m app.eval.selection_runner --rescore logs/eval/selection-<시각>.json
```

| 옵션 | 내용 |
|---|---|
| `--extraction-log` | 입력으로 사용할 추출 평가 결과 파일. 여러 번 지정 가능 |
| `--fixture` | 선택 정답표 이름(확장자 제외). 여러 번 지정 가능하며, 없으면 정답표가 있는 픽스처 전부 |
| `--runs` | 픽스처당 사용할 추출 결과 수(기본 5) |
| `--selector` | `llm`(선택 에이전트, 기본) 또는 `decision`(판단 선택 에이전트) |
| `--decision-profile` | 판단 선택의 판단 프로필. 없으면 `AGENT_DECISION_PROFILES` 기본값 |
| `--rescore` | 저장된 선택 결과를 모델 호출 없이 재채점 |

- 추출을 다시 호출하지 않는다. 추출 평가(`app.eval.runner`)가 저장한 결과 파일을 입력으로 사용하므로 선택 호출 비용만 발생한다. 추출 결과 하나마다 모드 A·B로 한 번씩 선택한다.
- 추출 프롬프트나 추출 모델이 다른 결과 파일을 함께 지정하면 실행하지 않는다. 추출이 바뀌면 모드 B 수치가 달라지기 때문이다.
- 결과 파일에는 선택 프롬프트 지문과 함께 입력으로 사용한 추출 결과 파일·추출 프롬프트 지문을 기록한다. 결과 파일의 지문은 가드레일까지 포함한 시스템 프롬프트 기준이며, 정답표 지문(3장)은 `prompt.md` 파일 기준이다.
- 판단 선택 평가는 질문 목록 지문을 기록하며, 판단 호출이 실패하여 전부 선택된 회차는 실패한 회차로 센다.
- 재채점 시 기록된 지문이 현재 선택 프롬프트(판단 선택이면 질문 목록)와 다르면 경고한다.

## 8. 한계

- 정답이 "선택 프롬프트대로라면 해야 할 선택"이므로(4장), 프롬프트 규칙 자체가 틀린 것은 검출하지 못한다.
- 모드 A의 글자 필드는 추출 결과이다. 추출이 `listing_text`에서 문구를 누락하면 A에서도 놓치므로 추출 탓으로 분류되지 않는다.
