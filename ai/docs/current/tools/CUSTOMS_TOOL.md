# 통관 요건 Tool

HS 품목분류 후보와 해당 HS의 세관장확인 요건 후보를 조회하는 Tool이다. 실행 틀, 원문 대조, 질문, 법령 조회 등 공용 동작은 [TOOL_COMMON.md](TOOL_COMMON.md)에서 설명한다.

## 1. 개요

- HS 품목분류는 관세청이 결정한다. 이 Tool은 유사한 품목분류 결정사례로 HS 후보를 찾고, 해당 HS의 세관장확인(관세법 제226조) 요건을 후보로 제시한다.
- 다른 Tool과 달리 요건 조회가 후보 선택 다음 단계에서 수행된다. HS 후보가 정해져야 요건을 조회할 수 있기 때문이다.
- 모델은 HS를 작성하지 않는다. 모델이 선택한 결정사례에 기재된 HS를 코드가 그대로 사용한다.
- 다루지 않는 범위: 목록통관·소액 면세와 세관장확인의 관계, 고시 별표 5(생략 대상 수출입자), HS 6자리 사례의 10자리 후보 탐색.

## 2. 입력

### 조건 필드

| 필드 | 표시 이름 | 질문 여부 |
|---|---|---|
| `product_type` | 제품 종류 | 항상 질문 (확인되지 않으면 조회하지 않음) |
| `material` | 재질 | 조건부 질문 (5장) |
| `function` | 기능 | 조건부 질문 (5장) |
| `intended_use` | 용도 | 질문하지 않음 |
| `composition` | 구성품 | 질문하지 않음 |

- 조건 추출 모델은 조건과 함께 결정사례 검색어(`search_terms`)를 출력한다. 검색어는 판단 근거가 아니므로 원문 대조 대상에서 제외한다.
- 모델 힌트에 속성 이름과 값을 포함한다(`hints_with_attributes`). 원문이 없는 속성도 검색어 결정에 참고한다.
- 인용할 원문이 없으면 제품 종류만 질문한다.

## 3. 처리 흐름

```text
① 조건 추출 (모델)      제품 종류·재질·기능·용도·구성품 + 원문 인용, 검색어
② 결정사례 조회 (코드)  DB 우선, 결과가 없으면 CLIP → 후보 8건
③ 결정사례 선택 (모델)  동일 물품의 사례 최대 3건 + 선택 이유
④ 요건 조회 (코드)      HS 10자리별 세관장확인 GW 조회
⑤ 요건 제외 (코드)      상품 신호·소재 표기상 해당하지 않는 요건 제외
⑥ 결과 조립 (코드)      법령별 판단 + 근거 + 할 일
```

- 모든 결과에 기본 가정 "HS 품목분류는 관세청이 정합니다. 비슷한 결정사례로 찾은 후보이며 확정이 아닙니다."를 포함한다.
- 제품 종류가 원문과 대조되지 않으면 ② 이후 단계를 수행하지 않고 정보 부족으로 종료한다.

### 3.1 결정사례 조회

검색어는 모델 검색어와 제품 종류를 합하여 구성한다.

- 여러 낱말로 된 검색어는 마지막 낱말(중심 명사)을 바로 다음 검색어로 추가한다. CLIP은 검색어를 구절 단위로 검색하므로 두 낱말 이상이면 결과가 매우 적기 때문이다.
- 중복을 제외한 뒤 최대 6개까지 사용한다.

순위 산정에 사용하는 상품 용어는 제품 종류, 재질 값, 상품명, 카테고리다.

| 경로 | 동작 |
|---|---|
| DB (`hs_cases`) | 검색어와 상품 용어를 줄 단위로 연결한 글 하나를 임베딩하여 유사한 사례 30건을 조회한다. HS가 없는 사례를 제외하고 유사도 순서를 유지한 채 상위 8건을 사용한다 |
| CLIP | DB에서 사례를 찾지 못했거나 DB 조회에 실패한 경우 사용한다. 검색어별로 30건을 동시에 조회하여 합한 뒤, 글자 유사도(`common.ranking.rank_rows`)로 8건을 선정한다 |

- `DATABASE_URL`이 설정되지 않으면 CLIP만 사용한다.
- DB 조회에 실패하면 일정 시간 DB 조회를 생략한다. 이 상태는 응답 캐시와 공유한다.
- CLIP 검색어 일부가 실패하면 나머지 검색어로 진행하고, 실패한 검색어를 `query.failed_terms`와 가정에 기록한다. 모든 검색어가 실패하면 Tool 오류로 처리한다.
- 결정사례 적재와 주간 갱신은 [DB_CACHE.md](../storage/DB_CACHE.md)에서 설명한다.

### 3.2 결정사례 선택

- 선택 모델에는 대조된 조건과 후보 사례를 입력한다. 사례별 설명은 앞 300자, 결정 이유는 앞 200자만 입력한다.
- 선택 결과는 공용 후보 선택 대조를 거친다([TOOL_COMMON.md](TOOL_COMMON.md) 5장). 대조되지 않은 선택이 있으면 그 수를 가정에 기록한다.
- 선택한 사례 중 후보 내에 한 건뿐인 호(HS 4자리)의 사례가, 여러 건 등장한 호의 사례와 함께 선택된 경우에는 제외하지 않고 "HS 확인이 필요합니다" 가정으로 표시한다(`query.lone_cases`).
- 동일 물품으로 볼 사례가 없으면 "세관장확인 비대상 판단이 아닙니다" 가정과 함께 정보 부족으로 종료한다.

### 3.3 세관장확인 요건 조회

- HS 10자리별로 관세청 세관장확인대상물품 GW(`DATA_GO_KR_KEY`)를 조회하여 대상 법령, 요건확인기관, 제출 서류를 확인한다.
- GW 응답은 DB(`api_response_cache`)를 우선 조회하고, 없으면 GW에서 수신하여 하루 동안 보관한다.
- 6자리 HS는 GW로 조회할 수 없으므로 "조회하지 못함"으로 처리한다.
- 빈 목록은 통관 단계의 세관장확인이 없다는 의미이며, 국내 판매 규제가 없다는 의미가 아니다.
- 법령 이름은 비교 키(`law_key`)로 묶어 법령별로 판단 하나를 생성한다.
  - 비교 키는 공백·가운뎃점 차이를 무시하고 끝의 괄호를 제거한다. GW가 "야생생물 보호 및 관리에 관한 법률(허가)"처럼 요건 종류를 덧붙이거나, 같은 법령을 요건확인기관 수만큼 반복하여 반환하기 때문이다.

## 4. 판정 규칙

### 4.1 결과 경우

| 경우 | 판정 | 위험도 | 제목 |
|---|---|---|---|
| HS 후보에 요건 법령이 있음 | `POSSIBLY_REQUIRED` (법령별) | `MEDIUM` | 세관 확인 서류가 필요할 수 있음 — {법령} |
| 조회 결과 요건 법령이 없음 | `NOT_REQUIRED` | `LOW` | 세관 확인 서류 필요 없음 |
| 위와 같으나 관세법 근거를 확인하지 못함 | `INSUFFICIENT_INFORMATION` | `LOW` | 세관장확인 대상 법령 — 조회되지 않음 |
| 요건이 있었으나 상품 정보에 따라 모두 제외됨 | `NOT_REQUIRED` | `LOW` | 세관 확인 서류 필요 없음 |
| 요건을 조회하지 못함 (6자리 HS 등) | `INSUFFICIENT_INFORMATION` | `UNKNOWN` | 세관 확인 서류 — 조회하지 못함 |
| 제품 종류 없음, 사례 없음, 해당 사례 없음 | `INSUFFICIENT_INFORMATION` | `UNKNOWN` | HS 품목분류·세관장확인 요건 |

- 한 번의 실행에서 여러 경우가 함께 발생하면 판단도 함께 생성된다. 예를 들어 요건이 있는 HS와 요건이 없는 HS가 동시에 존재할 수 있다.
- "필요 없음" 판단은 조회 결과이므로 정보 부족으로 처리하지 않으며, 관세법 제226조를 근거로 첨부한다.
- 다른 HS 후보가 별도로 존재하면 "필요 없음" 판단의 품목번호 줄 끝에 "(이 번호로 분류될 때)"를 덧붙인다.
- "필요 없음" 판단의 가정에는 다음 두 문장을 기록한다.
  - 다른 HS로 분류되면 요건이 생길 수 있음
  - 국내 판매 규제가 없다는 의미는 아님
- "모두 제외됨" 판단은 다른 판단이 하나도 없고 관세법 근거를 확인한 경우에만 생성한다. 근거를 확인하지 못하면 기본 정보 부족 판단을 생성한다. 제외한 법령별로 "{대상 물품}에만 필요한 서류는 제외했습니다." 한 줄을 요약에 추가한다.

### 4.2 상품 정보에 따른 요건 제외

GW는 HS 단위로 요건을 반환하지만, 일부 법령은 해당 HS 중 특정 물품에만 적용된다. 아래 경우에는 요건을 제외하고 제외 사유를 가정에 기록한다.

| 법령 | 제외 조건 |
|---|---|
| 총포·도검·화약류 등의 안전관리에 관한 법률 | 상품 신호 `weapon_like`가 `False`인 경우에만 제외. 알 수 없으면(`None`) 유지 |
| 야생생물 보호 및 관리에 관한 법률 | 소재 글에 가축 가죽 또는 인조 가죽 표기가 있고, 유지 대상 소재 표기가 없는 경우 |

야생생물법은 다음 규칙으로 판단한다.

- **소재 글:** 조건의 재질·구성품 값, 상품명, 원문 중 "소재·재질·material"이 포함된 줄을 대상으로 한다.
- **제외 가능 표기:** 소·송아지·양·돼지·염소 가죽, 인조·합성·PU·비건·PVC 가죽.
  - 송아지 가죽은 "카프스킨", "calfskin"처럼 가죽을 의미하는 말이 결합된 표기만 인정한다.
  - PVC는 "PVC 가죽"처럼 가죽을 의미하는 말이 결합된 표기만 인정한다.
- **유지 대상 표기:** 악어, 뱀, 도마뱀, 타조, 가오리, 상어, 코끼리, 상아, 모피. "fur"는 독립된 낱말인 경우에만 인정한다.
- 소재를 확인할 수 없으면 요건을 유지한다.
- 제외 가능 표기를 제거한 뒤에도 종류가 명시되지 않은 가죽 표기(가죽, 피혁, 레더, leather)가 남으면 요건을 유지한다.
- 판매자 답변 줄(`[사용자 답변]`)에 제외 가능 소재가 있으면 답변 줄만 판단 대상으로 한다. 이 경우 상품명·원문의 "가죽"은 답변으로 종류가 명시된 것으로 간주한다.

### 4.3 일부 물품에만 해당하는 법령

아래 법령은 HS 전체에 대해 반환되지만 일부 물품에만 해당한다. 판단 요약과 할 일에서 대상 물품을 서류보다 먼저 기재한다(`rules.LAW_CONDITIONS`). 상품별로 요건을 제외하지는 않는다.

| 법령 | 대상 물품 |
|---|---|
| 야생생물 보호 및 관리에 관한 법률 | 악어·뱀 등 멸종위기종(CITES) 가죽이나 부위를 쓴 제품. "소가죽 등 일반 가축 가죽 제품은 해당하지 않습니다." 줄을 덧붙임 |
| 약사법 | 의약품·의약외품·한약재·동물용 의약품 |
| 의료기기법 | 의료기기(동물용 포함) |
| 생활화학제품 및 살생물제의 안전관리에 관한 법률 | 세정제·세탁세제·방향제·탈취제·접착제 같은 안전확인대상 생활화학제품 |
| 화장품법 | 화장품(피부·모발에 바르거나 뿌리는 등으로 쓰는 물품) |
| 위생용품 관리법 | 「위생용품 관리법」에서 위생용품으로 정한 물품(대표 품목 예시 포함) |

### 4.4 다른 Tool이 판단하는 법령

세관장확인 요건 중 다른 규제 Tool이 제품 단위로 판단하는 법령은, 종합 단계(`pipeline/aggregator.py`)에서 해당 Tool의 판단과 일치시킨다(`related.follow_related_tools`). 통관 Tool은 다른 Tool과 병렬로 실행되어 그 결과를 참조할 수 없기 때문이다.

| 법령 | 담당 Tool | 반영하는 판단 |
|---|---|---|
| 전기용품 및 생활용품 안전관리법 | 전기용품 | 대상, 대상 후보, 대상 아님 |
| 어린이제품 안전 특별법 | 어린이제품 | 대상, 대상 후보, 대상 아님 |
| 전파법 | 전파 | 대상, 대상 후보만 (Tool 범위가 법 범위보다 좁음) |
| 수입식품안전관리 특별법, 식품위생법, 의료기기법, 체외진단의료기기법, 화장품법, 약사법, 위생용품 관리법 | 식품·의약품 | 반영하지 않음 (Tool 하나가 여러 법령을 판단) |

- 담당 Tool이 선택되지 않았거나, 실패했거나, 정보 부족으로 판단한 경우에는 반영하지 않는다.
- 담당 Tool의 판단이 여러 개이면 대상 > 대상 후보 > 정보 부족 > 대상 아님 순으로 하나로 집약한다.
- 반영 시 판단을 삭제하지 않고 판정·제목·요약을 변경한다.

  | 반영한 판정 | 제목 | 요약 둘째 줄 | 할 일 |
  |---|---|---|---|
  | 대상 | 세관 확인 서류 필요 — {법령} | 통관 때도 서류를 내야 합니다 | 유지 |
  | 대상 후보 | 세관 확인 서류가 필요할 수 있음 — {법령} | 대상이면 통관 때도 서류를 내야 합니다 | 유지 |
  | 대상 아님 | 세관 확인 서류 필요 없음 — {법령} | 통관 서류도 필요하지 않습니다 | 삭제, 위험도 `LOW` |

  요약 첫 줄은 "- {분야} 분야 판단을 따릅니다: {판정}"이다.
- 반영한 법령은 `query.followed_requirements`와 종합 결과의 가정에 기록된다.
- 담당 Tool이 있는 법령은 통관 Tool 실행 시 판단 가정에 "같은 법의 제품 판단은 {분야} Tool 결과와 함께 봐야 합니다."를 기록하고 `query.related_tools`에 저장한다. 검증 단계에서 같은 법의 제품 판단과 함께 검토하도록 하기 위함이다.

## 5. 화면 문구

### 판단 요약

요건 후보 판단의 요약은 할 일과 같은 표현을 사용하여 줄 단위로 작성한다.

```text
- 품목번호: HS 8516.79-9000 후보
- 미리 갖출 서류: {서류}
```

- 일부 물품에만 해당하는 법령은 서류 줄을 "- {대상 물품}에 해당하면 미리 갖출 서류 …"로 시작한다.
- 서류를 확정하지 못한 경우 서류 줄 대신 "{대상 물품}에만 해당합니다." 한 줄을 기재한다.
- 판단 근거(`rationale`)는 결정사례 선택 모델이 사례별로 작성한 선택 이유를 줄 단위로 연결한 것이다.

### 할 일

법령별로 한 건을 생성하며 줄바꿈으로 구분한다. 화면은 줄바꿈을 그대로 표시한다.

```text
[{법령}] · 품목번호 HS {HS 후보} 후보
수입 통관 때 세관에 아래 서류를 내야 할 수 있습니다.
- 미리 갖출 서류: {서류} (관세법 제226조, 세관장확인 고시 별표 2)
- {구매대행 줄}
```

- **둘째 줄:** 일부 물품에만 해당하는 법령은 "이 품목번호로 분류되고 {대상 물품}에 해당하면, 통관 시 아래 서류가 필요할 수 있습니다."로 기재한다.
- **서류 이름:** 고시 별표 2 구비요건 문구를 사용한다. 없으면 GW 서류명을, 둘 다 없으면 "해당 법령의 요건 확인 서류"를 사용한다.
- **서류가 여러 개인 경우:** "- 미리 갖출 서류 (물품에 따라 해당하는 것 · 관세법 제226조, 세관장확인 고시 별표 2)" 아래에 서류별로 "· …" 한 줄씩 기재한다. 판단 요약에는 근거 조문을 기재하지 않는다.
- **대상과 서류의 대응:** 별표 2 범위 칸의 (가)(나)… 항목 수와 구비요건 항목 수가 같으면 "{대상}: {서류}" 형식으로 대응시킨다.
- **삭제된 항목:** 별표에서 삭제된 항목은 제외한다.
- **구매대행 줄:** 고시 제7조 제2항 제1호 단서에 따라 결정한다.

  | 경우 | 문구 |
  |---|---|
  | 단서에 포함된 법령 | 구매대행도 해당 (고시가 범위를 한정한 경우 "(고시 조건: …)" 덧붙임) |
  | 단서에 포함되지 않은 법령 | 구매대행: 구매자 개인이 쓰려고 들여오는 경우 등에는 생략될 수 있음 |
  | 고시를 확인하지 못했거나 법령을 별표 2와 대응시키지 못함 | 구매대행: 생략 여부를 확인하지 못함 |

- **덧붙임 줄:** 야생생물법은 마지막에 "- 소가죽 등 일반 가축 가죽 제품은 해당하지 않습니다." 줄을 덧붙인다.
- **요건을 조회하지 못한 HS:** "[HS … 후보] 수입 전 관세청 UNI-PASS 세관장확인대상 조회 또는 관세사를 통해 HS 분류와 요건을 확인해야 합니다."를 할 일로 생성한다.
- **판단별 할 일:** 판단마다 해당 법령의 할 일을 `requirements`에 저장한다. 재실행에서 판단이 제외되면 Tool 실행기가 해당 할 일만 삭제한다.

### 질문

HS 분류에 영향을 주는 조건(제품 종류·재질·기능)만 질문한다.

- 선택 모델이 추가로 필요하다고 표시한 그 밖의 조건(용도·구성품)은 질문하지 않고, "HS 확정에는 … 확인이 더 필요합니다." 가정으로 기록한다.
- 재질·기능은 후보 HS 사이에 세관장확인 요건이 다르거나, 요건을 조회하지 못한 후보가 있는 경우에만 질문한다.
  - 요건이 같으면 "… 확인이 더 필요하지만, 후보 HS에 따라 갈리는 세관장확인 요건이 없어 묻지 않았습니다."로 기록한다.
  - 요건 비교 시 다른 Tool의 판단을 그대로 반영하는 법령(전기용품법·어린이제품법)은 비교 대상에서 제외한다.
- 소재에 따라 제외될 수 있는 요건(야생생물법)이 남아 있고 재질을 알 수 없거나 종류가 명시되지 않은 가죽인 경우, 모델의 요청이 없어도 재질을 질문한다.
  - 유지 대상 소재가 이미 확인되었으면 질문하지 않는다.
  - 이전 회차에 재질을 이미 질문했으면 다시 질문하지 않고, "판매자 답에서 가죽 종류를 확인하지 못해 남겼습니다."로 끝나는 가정을 기록한다.

### 화면 근거 요약

판단 근거의 줄 수가 결정사례 근거 수와 같고 두 줄 이상이면, 공개 진단서는 근거를 다음 두 줄로 요약한다(`results/presenter.py`).

```text
판단: {첫 줄}
참고 사례: N건 · HS … · 아래 '근거'에서 확인
```

## 6. 근거

| 문서 | 용도 |
|---|---|
| 관세법 제226조 | 모든 요건 판단과 "필요 없음" 판단의 근거 |
| 세관장확인물품 및 확인방법 지정고시 별표 2 | GW 법령 이름으로 행을 찾아 "대상 법령 및 물품의 범위", "구비요건" 원문 인용 |
| 같은 고시 제7조 제2항 | 대외무역법 시행령 제19조 사유 물품의 세관장확인 생략과 단서 법령. 구매대행 줄의 근거 |
| 대외무역법 시행령 제19조 | 수출입승인 면제 사유. 구매대행 줄의 근거 |
| 관세청 품목분류 결정사례(CLIP) | 선택한 결정사례. 인용은 "물품명 — 결정 이유 앞 200자", 조문 칸은 "결정사례 {ID} (HS …)" |

- 요건 판단의 근거는 관세법 제226조 → 별표 2 행 → (생략 판단이 있으면) 고시 제7조·대외무역법 시행령 제19조 → 결정사례 순으로 첨부한다.
- 결정사례는 공개 열람 주소가 없으므로 `source_url`을 비워 둔다.
- 근거 조문에 판단에 사용하는 문구("세관장", "상행위", "생략")가 없거나 별표 2를 유일하게 특정하지 못하면, 근거 없이 안내를 계속한다. 이때 "관세법·세관장확인 고시의 시행 버전·본문을 확인하지 못해 근거 조문 없이 안내했습니다." 가정을 기록한다.
- 고시 제7조의 단서 목록만 확인하지 못한 경우 관세법·별표 2 근거는 사용하고, 구매대행 줄은 "확인하지 못함"으로 처리한다.
- 법령 이름은 비교 키로 별표 2 행과 대응시킨다.

## 7. 실패·정보 부족

| 상황 | 처리 |
|---|---|
| 조건 추출·결정사례 선택 모델 실패 | `CustomsToolError` |
| 결정사례 조회 실패 (CLIP 검색어 전부 실패 등) | `CustomsToolError` |
| GW 요건 조회 실패 | `CustomsToolError` |
| 근거 법령 조회 실패 | `CustomsToolError` |
| 근거 법령의 버전·본문을 확인할 수 없음 | 근거 없이 진행, 가정에 기록 |
| 6자리 HS | 해당 HS만 "조회하지 못함" 판단 |
| 제품 종류 없음, 사례 없음, 해당 사례 없음 | 정보 부족 판단. 비대상으로 해석하지 않음 |

## 8. 상세 결과와 조회 기록

`CustomsAssessment`:

| 칸 | 내용 |
|---|---|
| `hs_code_candidates` | HS 후보 (표기 "8516.79-9000", 6자리는 "8516.79") |
| `applicable_requirements` | 남은 요건 법령 |
| `required_documents` | 판매자에게 안내한 서류 |
| `customs_confirmation_required` | 아래 표 참고 |

`customs_confirmation_required` 값:

| 값 | 경우 |
|---|---|
| `false` | HS 후보를 모두 조회했고 판단이 모두 "필요 없음"인 경우. 종합 단계에서 다른 Tool 판단을 반영하여 마지막 요건이 삭제된 경우에도 같은 기준을 적용 |
| `null` | 그 밖의 경우 |

`query` 주요 키:

| 키 | 내용 |
|---|---|
| `search_terms`, `failed_terms` | 결정사례 검색어와 실패한 검색어 |
| `candidate_cases`, `selected_cases`, `lone_cases` | 후보, 선택한 사례, 한 건뿐인 호로 표시한 사례 |
| `hs_candidates`, `requirements` | HS 후보와 HS별 요건 법령 (조회한 HS만) |
| `excluded_requirements` | 상품 정보에 따라 제외한 HS별 법령 |
| `related_tools`, `followed_requirements` | 다른 Tool이 판단하는 법령과 종합 단계에서 반영한 법령 |
| `documents` | 근거 문서 버전 |
| `dropped_facts`, `dropped_candidates`, `not_applicable`, `over_limit` | 공용 대조 기록 ([TOOL_COMMON.md](TOOL_COMMON.md)) |

```bash
cd ai
python -m pytest tests/tools/customs tests/tools/test_registry.py -q
```

- 법제처·CLIP은 실제 응답 픽스처를, GW와 모델은 가짜 구현을 사용한다. GW 가짜 구현은 실제 응답 형식을 따른다.
